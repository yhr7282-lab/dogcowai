# 자동 운영 설계와 사용법

목표는 "AI가 초안을 만들고, 검사를 통과한 것만 사람이 승인해 게시"하는 것이다.
지금 구현된 것과 아직 연결하지 않은 것을 구분해 적는다.

## 단계와 현재 상태

| 단계 | 하는 일 | 도구 | 상태 |
|---|---|---|---|
| A. 수집 | 후보 기사 목록(제목, 주소, 출처, 시각, 분야)을 모은다 | AI 에이전트의 웹 검색, 공식 RSS | 수동(에이전트가 수행). 전용 수집기는 없음 |
| A-2. 중복 제거 | 같은 사건을 묶고 가장 이른 보도와 독립 출처 수를 센다 | `tools/candidates.py` | 구현, 테스트 있음 |
| B. 생성 | 원문을 읽고 `content/날짜.json` 초안을 쓴다 | AI + `docs/prompts/briefing.md` | 프롬프트 준비. API 자동 호출은 연결 안 함 |
| C. 검증 | 형식, 출처 유무, 날짜, 숫자 일치, 개인정보, 링크 | `tools/build.py --check`, `tools/check_links.py`, 테스트 | 구현, 테스트 있음 |
| D. 승인 | 미리보기와 변경 내용을 사람이 확인 | 브랜치 + 화면 캡처 | 수동 |
| E. 게시 | main 에 합치고 실제 사이트를 확인 | git push, GitHub Pages | 수동(승인 후) |

단계는 서로 독립이다. 어느 단계가 실패해도 `build.py`는 아무 파일도 쓰지 않으므로 공개 사이트는 그대로다.

## 규칙으로 잡는 것과 사람이 봐야 하는 것

| 검사 | 방법 |
|---|---|
| 필수 항목, 날짜 형식, 기사 id 중복 | 자동 (`build.py`) |
| 기사에 출처가 있는가, 출처 주소가 중복되는가 | 자동 |
| 핵심 1분이 기사에 연결되고 숫자가 본문에 있는가 | 자동 |
| 기사 날짜가 브리핑 날짜보다 뒤인가, 시장 수치 기준일이 오래됐는가 | 자동 |
| 이미 지난 일정이 '다음 일정'에 있는가 | 자동 |
| 금지 패턴, 개인 전용 블록 | 자동 (목록에 있는 것만 잡는다) |
| 링크가 열리는가, 안내 페이지인가 | 자동 (`check_links.py`). 접근 제한은 따로 표시 |
| **링크의 내용이 숫자와 날짜를 뒷받침하는가** | 원문 대조 필요. 자동 검사로 대신할 수 없다 |
| 과장된 제목, 홍보성 표현, 이전 판과의 반복 | 사람 또는 AI 검토 |
| 새로운 종류의 개인 정보 | 사람 |

## 게시를 막는 조건
1. 출처가 없는 기사가 있다
2. 핵심 숫자가 원문과 다르다
3. 개인 정보가 있다
4. 출처끼리 사실이 충돌하는데 정리되지 않았다
5. 생성 또는 링크 검사가 실패했다
6. 원문 확인 없이 쓴 주장이 있다

1, 3(목록 범위), 5는 도구가 막는다. 2, 4, 6은 원문 대조 기록으로 확인한다. 확인하지 못한 문장은 뺀다.

## 상황별로 하는 일 (운영자용)

**오늘 브리핑을 만들 때**
Claude Code에 "오늘 브리핑 만들어서 미리보기 보여줘"라고 한다. Claude가 후보 수집, 원문 대조, 내용 파일 작성, 검사를 하고 화면 캡처를 보낸다.

**작성된 브리핑을 검토할 때**
캡처에서 헤드라인, 숫자, 출처를 본다. 고칠 곳은 말로 알려 준다. 원문 대조 결과(확인됨, 접근 제한, 확인 안 됨)도 함께 받는다.

**게시를 승인할 때**
"반영해"라고 하면 main 에 합쳐 올린다. 1~2분 뒤 사이트에 나온다. 승인 전에는 사이트가 바뀌지 않는다.

**오류가 났을 때**
검사가 실패하면 사이트는 이전 상태 그대로다. 오류 메시지는 파일, 위치, 규칙만 알려 준다. Claude에 "오류 고쳐줘"라고 하면 된다.

**지난 브리핑을 고칠 때**
"10월 13일 브리핑에서 ○○ 고쳐줘"라고 한다. 고친 내용은 그 페이지의 '정정·수정 내역'에 날짜와 함께 남긴다.

## 예약 실행
- 목표 시각은 아침판 05:00, 오후판 17:00 (한국 시간)이다. 예약 도구는 늦게 돌 수 있으므로 "그 시각에 반드시"가 아니라 "그 시각 이후 가능한 빨리"로 본다.
- 근거가 부족하면 새 판을 만들지 않고 이전 판을 유지한다. 확인하지 않은 뉴스를 갱신된 것처럼 표시하지 않는다.
- 같은 날짜는 파일이 하나라서 중복 실행해도 결과가 겹치지 않는다. 같은 날짜의 새 판은 이전 판 기사를 `earlier`로 옮겨 주소를 남긴다.

두 가지 방식이 있다.

| 방식 | 장점 | 걸림돌 |
|---|---|---|
| Claude 예약 작업이 브랜치에 초안을 올리고 사람이 승인 (권장) | 웹 검색과 원문 대조를 에이전트가 직접 한다. 추가 API 키가 필요 없다 | 예약 작업 등록은 승인 필요 |
| GitHub Actions 가 AI API 를 호출 | 저장소 안에서 완결 | AI API 키와 비용 상한 설정이 필요. 키가 없으면 동작하지 않는다 |

검사만 하는 워크플로 예시는 `docs/automation/briefing-check.yml.example`에 있다. 지금 쓰는 GitHub 로그인에는 워크플로 파일을 올릴 권한(`workflow`)이 없어서 활성화하지 않았다.

## 노션을 원본으로 쓸 때
개인용 노션 원문에는 개인 정보가 있다. 원문 전체를 저장소나 GitHub Actions, 외부 서비스로 보내지 않는다. 공개할 내용만 골라 내용 파일로 옮긴다.

## 비용
- 현재 고정비: 호스팅 0원 (GitHub Pages). 도메인과 메일 비용은 기존 그대로다.
- AI 초안 작성: Claude Code 구독 범위에서 수행하면 추가 비용이 없다. API 로 자동 호출하면 사용량만큼 과금되므로 월 상한을 제공사 콘솔에서 먼저 설정한다. 호출량을 측정하기 전에는 금액을 추정하지 않는다.
