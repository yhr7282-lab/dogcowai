# 자동 운영 설계와 사용법

2026-10-24부터 자동 제작기 v2로 돈다. 뉴스 조사와 노션 저장은 ChatGPT 예약(매일 05:00·17:00 KST)이 하고,
공개 변환·사이트 생성·게시는 이 컴퓨터의 자동 제작기(`~/.dogcowai-runner`, 공개 저장소 밖)가 한다.
규칙의 기준은 노션 'dogcowai 하루 두 번 제작·리뷰 운영 규칙' 맨 위 '2026-10-24 뉴스요약·사이트 연동 v2'다.

## 원본: 노션 '오늘의 브리핑' v2
한 페이지에 공개 구역과 개인 구역이 나뉘어 있다.
- 첫 줄 `판 {ID} · 형식 v2 · 개정 {n} · 상태 {작성중/검증완료} · 결과 {UPDATED/NO_CHANGE} · 뉴스 확인 · 저장`
- `공개 시작 · 판 {ID} · 개정 {n}` … 공개 브리핑 … `공개 종료 · 판 {ID} · 개정 {n}`
- 그 아래 개인 브리핑과 비공개 제작 점검 (읽어도 옮기지 않는다)
- 마지막 줄 `저장 완료 · 판 {ID} · 형식 v2 · 개정 {n} · 공개 기사 {N} · 저장 {ISO}`
네 표지의 판 ID·개정이 모두 같고 상태가 검증완료인 판만 처리한다. 한 줄의 완료 표시만 믿지 않고 다시 읽어 개정이 그대로인지 본다.

## 한 회차의 흐름
회차 = 판 ID (`YYYY-MM-DD-AM` / `-PM`). 상태는 실행기의 `state/editions/<판 ID>.json` 에 남는다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 0. 관문 | `gate.sh` (launchd, 05:05·05:20·05:35·05:50·06:20·06:50 / 17:05~18:50 같은 간격) | 상태 파일만 보고, 이미 끝난 회차·실행 중·시간대 밖이면 창을 열지 않고 끝난다 |
| 1. 제작 | Claude (푸시가 막힌 환경) | 노션 공개 구역만 읽어 후보 목록(`source.json`)·결정(`decisions.json`)을 남기고 `content/날짜.json` 을 쓴 뒤 생성·검사. 기다리지 않고 RESULT 한 줄로 끝낸다 |
| 2. 검사·게시 | `run-briefing.sh` | 바뀐 파일이 `content/`·생성 결과뿐인지, `tools/edition_check.py`(표지·개정 일치, 후보 수 = 반영 + 제외, 반영한 기사가 실제로 있는지)를 본 뒤 맨 위 시장 지표 12개를 지금 값으로 넣고(`tools/market_snapshot.py`, 실패해도 게시는 막지 않음), 테스트·생성 검사·링크 검사를 모두 통과해야 커밋·푸시. 실제 사이트의 일별 페이지가 커밋한 파일과 같아지는지 확인 |
| 3. 기록 | Claude | 노션 '제작·리뷰 이력'에 회차 결과를 한 번만 남긴다 (커밋 SHA, 배포 확인 시각, review_due_at = 확인 + 60분) |

회차 결과
- `published`: 게시하고 실제 사이트에서 확인했다. 같은 판 ID 는 다시 게시하지 않는다 (같은 회차 안의 늦은 개정은 다음 판에서 반영).
- `no_change`: 원본 결과가 NO_CHANGE 이거나 이미 게시한 개정이다. 개인 구역만 바뀐 판도 여기다.
- `waiting` / `incomplete`: 원본이 아직 이번 판이 아니거나 미완성이다. 다음 예약 시각에 다시 본다.
- `failed_checks`: 검사에 걸려 게시하지 않았다. 작업 사본은 되돌리고 다음 예약 시각에 처음부터 다시 만든다.
- `limited`: Claude 사용량 한도. 다음 예약 시각에 다시 시도한다.
- `delayed_final`: 회차 마지막 예약까지 준비되지 않았다. 노션에 지연을 한 번 기록하고, 다음 회차에 소급 게시하지 않는다.
어느 경우든 실패하면 공개 사이트는 이전 상태 그대로다.

## 규칙으로 잡는 것과 사람이 봐야 하는 것

| 검사 | 방법 |
|---|---|
| 공개 입력의 항목이 허용 목록에 있는가 | 자동 (`build.py` ALLOWED) |
| 필수 항목, 날짜 형식, 기사 id 중복, 출처 유무·중복 | 자동 (`build.py`) |
| 핵심 1분이 기사에 연결되고 숫자가 본문에 있는가, 대표 제목과 같은 문장이 아닌가 | 자동 |
| 시장·일정 줄마다 근거 링크가 있는가 (v2 판부터) | 자동 |
| 앞선 기사(follows)·정정 대상(ref)이 실제로 있는가 | 자동 |
| 금지 패턴·개인 문맥 규칙 | 자동 (막는다). 주의 단어는 위치만 알린다 |
| 표지·개정 일치, 후보 수 = 반영 + 제외 | 자동 (`edition_check.py`) |
| 제작 단계가 코드·문서를 바꾸지 않았는가 | 자동 (`run-briefing.sh`) |
| 링크가 열리는가 | 자동 (`check_links.py`) |
| **링크의 내용이 숫자와 날짜를 뒷받침하는가** | 제작 단계의 원문 대조. 자동 검사로 대신할 수 없다 |
| 과장된 제목, 이전 판과의 반복, 새로운 종류의 개인 정보 | ChatGPT 리뷰(배포 확인 + 60분)와 사람 |

## 상황별로 하는 일 (운영자용)
- **자동 제작 멈추기**: 터미널에서 `launchctl bootout gui/$(id -u)/com.dogcowai.briefing`
- **다시 켜기**: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.dogcowai.briefing.plist`
- **한 회차를 직접 다시 돌리기**: 그 회차 상태 파일을 지우고 `FORCE=1 bash ~/.dogcowai-runner/run-briefing.sh`
- **기록 보기**: `~/.dogcowai-runner/run-briefing.log`(제작), `gate.log`(건너뛴 예약), `state/editions/`(회차 상태)
- **지난 브리핑 고치기**: 그 날짜 파일의 `corrections` 에 `ref` 를 붙여 적는다. 고친 기사 페이지에도 정정이 나온다.

- 고정비: 호스팅 0원 (GitHub Pages). 도메인·메일 비용은 기존 그대로.
