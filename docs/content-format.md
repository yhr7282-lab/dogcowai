# 내용 파일 형식

`content/YYYY-MM-DD.json` 한 파일이 하루치 브리핑 한 페이지가 된다. 예시는 `content/2026-10-13.json`.
고정 페이지는 `content/pages/이름.json`이다. 지금은 없다 (소개 페이지는 2026-10-24에 없앴다).

## 공개 입력 규칙
- 개인 내용은 처음부터 넣지 않는다. `actions`, `side.career`, `private` 표시는 생성 실패다.
- 아래 표에 있는 항목만 쓸 수 있다 (`tools/build.py`의 `ALLOWED`). 다른 항목이 있으면 그 항목 이름만 알리고 생성이 멈춘다.
  노션 원본의 판 상태·개정·사건 키·수치 근거 줄 같은 운영 정보는 옮기지 않는다.
- 금지 규칙은 세 가지다. 걸리면 생성이 멈춘다: `_site.json`의 `blocklist`(일반 패턴), `context_rules`(개인을 가리키는 말 가까이에 민감한 단어가 붙은 문맥),
  로컬 전용 `보관/blocklist.local.txt`(특정 이름·수치).
- 주의 단어(`review_terms`: 월세·보증금·분양가 등)는 공공 정책 기사에도 나오므로 막지 않고 위치만 알린다. 제작자는 그 문장이 공개 기사 문맥인지 확인하고, 개인 사정이면 지운다.
- 금지 패턴(`_site.json`의 `blocklist`, 로컬 전용 `보관/blocklist.local.txt`)이 어느 문자열에라도 있으면 실패다.
- 실패하면 파일·위치·규칙만 알려 주고 아무것도 쓰지 않는다.

## 글 안에서 쓸 수 있는 표시
| 쓰는 법 | 결과 |
|---|---|
| `**굵게**` | 굵은 글씨 |
| `{{down:-5.46%}}` | 파랑 굵은 글씨 (하락) |
| `{{up:+1.8%}}` | 빨강 굵은 글씨 (상승) |

## 최상위 항목
| 항목 | 필수 | 설명 |
|---|---|---|
| `date` | 예 | `2026-10-13`. 파일 이름과 같아야 한다 |
| `headline`, `summary` | 예 | 대표 제목(한 가지 중심 사건)과 그 의미 1~2문장. 둘이 같은 문장이면 실패. v2 판부터 summary 는 110자 이내 |
| `lead_ref` | v2부터 예 | 대표 제목이 다루는 기사의 id. 그 기사는 제목이 더 크게 보인다 |
| `sections` | 예 | 분야 목록. 기사가 없는 분야는 화면에 나오지 않는다 |
| `edition` | | `오후판` 등 |
| `checked_at` | | `17:02 KST` 형식. 뉴스를 마지막으로 확인한 시각. 모르면 넣지 않는다 |
| `market` | | 시장 요약 |
| `quick` | | 핵심 1분. 기사에 연결한다 |
| `side.schedule` | | 다음 일정 |
| `updated_at` | | 게시한 판을 고친 시각. `2026-10-14T10:47:00+09:00`처럼 시간대를 붙이거나, 시각을 모르면 `2026-10-14`처럼 날짜만 쓴다. 브리핑 기준 시각보다 이를 수 없다. 화면에는 '수정 10월 14일 10:47 KST'로 나오고, 피드와 검색용 정보에도 쓰인다. 새 판을 쓸 때는 넣지 않는다 |
| `corrections` | | 정정·수정 내역 `[{"date", "text", "ref"}]`. `ref`(선택)는 고친 기사의 id 이고, 그 기사 페이지에도 '이 기사의 정정'으로 나온다 |
| `earlier` | | 이전 판 기사. 같은 날짜의 새 판에서 뺀 이전 판 기사를 고치지 않고 옮겨 둔다 `[{"edition", "checked_at", "sections": [분야]}]`. 기사 주소와 페이지가 그대로 남고, 브리핑에는 '오전판에 실린 기사'처럼 판 이름 아래 제목 줄만 나온다. 아래 '같은 날짜의 새 판' 참고 |
| `withdrawn` | | 철회. 게시했다가 내린 기사 `[{"id", "reason"}]`. 그 주소에는 기사 내용 없이 사유만 적은 안내 페이지가 남는다 (검색 제외). 사유는 공개해도 되는 짧은 문장으로 쓴다 |

## 기사 (sections[].items[])
```json
{
  "id": "kospi-sidecar",
  "date": "2026-10-13",
  "featured": true,
  "title": "제목",
  "teaser": "날짜별 브리핑의 기사 목록과 기사 페이지에서 제목 아래에 붙는 한 줄 (선택).",
  "facts": "무슨 일이 있었나. 확인한 사실만.",
  "so": "왜 중요한가. 근거가 있을 때만.",
  "recheck": {"label": "다시 볼 조건", "text": "다음에 확인할 것."},
  "sources": [{"name": "매체", "url": "https://..."}]
}
```
- `id`: 영문 소문자·숫자·하이픈. 그날 브리핑 안에서 유일해야 한다. 기사 주소가 된다: `/news/날짜/id/`. 게시한 뒤에는 바꾸지 않는다 (주소가 바뀐다).
- `date`: 사건이나 발표 날짜. 브리핑 날짜보다 뒤일 수 없다.
- `sources`: 하나 이상 필수 (`_site.json`의 `require_sources_from` 날짜부터). 같은 주소를 두 번 쓰면 실패다.
- `teaser`: 날짜별 브리핑(`/news/`)의 기사 목록에서 제목 아래에 붙는 한 줄이고, 기사 페이지의 제목 아래 요약과 검색·공유 설명문으로도 쓴다. 홈과 일별 브리핑에는 본문이 모두 나오므로 쓰지 않는다. 한 문장, 30~60자를 목표로 하되 정확성이 먼저다. 없으면 `facts`의 첫 문장이 나온다. 숫자를 쓰면 그 숫자가 기사의 제목이나 본문에 그대로 있어야 한다. 기사 본문은 바뀌지 않는다.
- `featured`: 분야 안에서 이 기사를 맨 위에 둔다. 나머지는 입력 순서대로다.
- `status`(선택): `신규`·`진전`·`보완`. 화면에는 진전·보완만 제목 아래 작은 글자로 나온다.
- `basis`(선택, 24자 이내): 근거의 상태를 짧게. 예: "단일 보도", "잠정치", "회사 전망", "익명 소식통 보도". 포괄적인 '검증 완료' 같은 말은 쓰지 않는다.
- `follows`(선택): 다른 날의 앞선 기사 `{"date", "id"}`. 그 기사로 가는 '앞선 기사' 줄이 붙는다. 같은 날의 진전은 follows 대신 같은 id 를 쓴다.
- `so`, `recheck`는 없으면 화면에서 그 구역이 빠진다.

## 분야 (sections[])
- `id`: 영문 소문자·숫자·하이픈. 같은 분야는 날짜가 달라도 같은 id 를 쓴다. 브리핑 안에서 분야 위치(`#id`)가 된다. 분야별 페이지는 없다.
- `title`: 분야 이름. 브리핑에서 분야 제목이 되고, 누르면 그 분야의 지난 기사 목록으로 간다.
- `lede`, `points`: 화면에 나오지 않는다 (기사 내용과 겹친다). 쓰지 않아도 된다.
- 홈과 일별 브리핑에는 분야마다 기사 내용이 모두 펼쳐져 나온다 (제목, 무슨 일이 있었나, 왜 중요한가, 다시 볼 조건, 출처). 기사 페이지에도 같은 내용이 있다 (공유·검색용 주소).

## 같은 날짜의 새 판 (게시한 기사 주소 지키기)
게시한 기사 주소는 지우지 않는다. 공유되거나 검색에 걸린 주소가 깨지지 않게 하려는 것이다.
- 이전 판에 실렸던 기사를 새 판에도 실으면 같은 `id`로 쓴다. 주소는 그대로이고 내용만 새 판 것으로 바뀐다.
- 새 판에서 빼는 기사는 지우지 말고 `earlier`로 옮긴다. 내용은 고치지 않고, 그 판의 이름과 확인 시각을 함께 둔다. 이미 `earlier`에 있던 것도 그대로 둔다.
```json
"earlier": [
  {"edition": "오전판", "checked_at": "05:06 KST",
   "sections": [{"id": "economy", "title": "경제", "items": ["오전판 기사 그대로"]}]}
]
```
- `earlier` 기사도 같은 검사(출처 필수 등)를 받는다. 같은 `id`가 지금 판과 `earlier`에 함께 있으면 실패다. 핵심 1분(`quick`)은 지금 판 기사만 가리킨다. 기사 페이지에는 그 판의 이름과 확인 시각이 나온다.
- 게시한 기사를 내려야 할 때만 `withdrawn`에 `{"id", "reason"}`을 적는다. 그 기사는 `sections`와 `earlier`에서 뺀다. 필요하면 `corrections`에 알린다.
- 이미 만든 기사 페이지가 지금 판, `earlier`, `withdrawn` 어디에도 없으면 생성이 멈춘다 (게시하지 않는다).

## 핵심 1분 (quick)
```json
{"text": "KOSPI {{down:6,035.35 (-5.46%)}} 마감", "ref": "kospi-sidecar"}
```
`ref`는 기사 id다. 문장 속 숫자는 연결된 기사의 제목이나 본문에 그대로 있어야 한다. 다르면 실패다.
화면에서는 줄마다 같은 페이지의 그 기사로 이동하고, 앞의 세 줄이 조금 더 크게 보인다. headline 과 같은 문장은 쓸 수 없다.

## 시장 요약 (market)
```json
{"name": "KOSPI", "note": "참고", "basis": "10/13 종가", "asof": "2026-10-13",
 "value": "6,035.35", "change": "▼ 5.46%", "dir": "down"}
```
- `basis`: 화면에 보이는 기준 설명 (종가, 전일 종가, 전망치 등).
- `asof`: 기준일. 브리핑 날짜보다 뒤이거나 `market_max_age_days`보다 오래되면 실패다.
- `market.sources`: 판 전체의 출처 목록 (예전 형식).
- `source`: 줄마다의 근거 `{"name", "url"}`. v2 판부터 줄마다 있어야 한다. 막대는 그리지 않는다 (기준이 다른 수치를 한 척도에 놓지 않는다).

## 다음 일정 (side.schedule)
```json
{"at": "2026-10-14T08:30:00-04:00", "title": "미국 9월 CPI", "desc": "미국 동부 08:30"}
```
`at`은 시간대가 붙은 시각이다. 화면에는 한국 시간으로 바꿔 시간순으로 보여 준다. 브리핑 기준 시각보다 이르면 실패다.
줄마다 `source: {"name", "url"}`(공식 일정 링크)를 붙인다. v2 판부터 필수다.

## 사이트 설정 (content/_site.json)
| 항목 | 설명 |
|---|---|
| `brand`, `title`, `description` | 이름, 탭 제목, 홈 설명 |
| `base_url` | 대표 주소. `https://dogcowai.com` 형식, 끝에 `/` 없음 |
| `intro` | 홈 맨 위의 짧은 소개 `{heading, paragraphs[]}`. 제목 한 줄과 한 단락만 쓴다. 없으면 소개가 빠진다 |
| `footer_meta`, `disclaimer` | 맨 아래 문구 |
| `require_sources_from` | 이 날짜부터 기사 출처가 필수 |
| `market_max_age_days` | 시장 수치 기준일의 허용 범위 |
| `blocklist` | 금지 패턴 (공개 가능한 일반 패턴만) |
| `context_rules` | 개인 문맥 금지 패턴 (예: '본인' 가까이의 월세·보유 종목) |
| `review_terms` | 막지 않고 위치만 알리는 주의 단어 |
| `tagline` | 홈의 제호 아래 한 줄 소개 |
| `v2_from` | 이 날짜의 판부터 v2 규칙(lead_ref·짧은 summary·시장/일정 행별 source)을 적용한다 |

## 고정 페이지 (content/pages/*.json)
`slug`, `title`, `sections[{heading, paragraphs[], items[]}]`. 선택: `nav`(메뉴 이름), `lead`, `description`.
