# dogcowai.com 사이트 구조 설계

2026-10-13 승인. 날짜별 브리핑을 쌓아 가는 정적 사이트로 만든다.

## 목표
- 홈페이지가 있고, 하루에 한 번 그날의 브리핑이 별도 페이지로 쌓인다.
- 매일 하는 일은 "내용 파일 하나 추가 + 생성 프로그램 실행 + 올리기"로 끝난다.
- 그 과정을 나중에 예약 작업(클라우드 Claude)이 그대로 수행할 수 있어야 한다.

## 선택한 방식
날짜별 내용 파일(JSON)에서 페이지를 만드는 작은 생성 프로그램(`tools/build.py`, 표준 라이브러리만 사용).
기각한 방식: GitHub 내장 Jekyll(디자인 이식과 디버깅이 어려움), 날짜별 HTML 수동 복사(홈·목록을 매번 손으로 갱신해야 함).

## 구조
```
index.html                      홈: 소개, 오늘의 주요 뉴스, 옆 칸(시장 막대, 지난 브리핑, 분야)
news/index.html                 날짜별 브리핑 목록
news/YYYY-MM-DD/index.html      하루치 브리핑: 헤드라인, 핵심 1분, 분야별 기사 목록, 시장 요약, 일정
news/YYYY-MM-DD/기사id/index.html  기사 하나
topic/index.html                분야 목록
topic/분야id/index.html          그 분야의 기사 목록 (모든 날짜)
about/index.html 등              고정 페이지
404.html, sitemap.xml, robots.txt, feed.xml
content/YYYY-MM-DD.json         그날의 내용 (원본)
content/_site.json              사이트 공통 설정
content/pages/*.json            고정 페이지 내용
assets/style.css                디자인
tools/build.py                  생성 프로그램
tools/templates/base.html       페이지 공통 틀
tools/test_build.py             테스트
CNAME, .nojekyll                도메인 연결 (건드리지 않는다)
```
위 HTML 은 모두 자동 생성이다. 손으로 고치지 않는다.

## 화면
- 홈: 최신 브리핑의 헤드라인·요약·시장 요약·핵심 1분, 지난 브리핑 목록, 전체 보기 링크
- 목록: 월별로 묶은 날짜별 브리핑
- 일별: 기존 디자인 그대로, 이전/다음 브리핑 이동 추가
- 내부 링크는 `index.html`을 명시해서 파일로 열어도 동작한다.

## 일별 업데이트 흐름
노션 '오늘의 브리핑' → `content/날짜.json` 작성 → `python3 tools/build.py` → 커밋·푸시 → 1~2분 뒤 반영.
하루에 한 페이지이며, 같은 날 여러 번 갱신하면 마지막 판이 남는다.

## 공개 규칙
- 공개 입력(`content/*.json`)에는 개인 내용을 두지 않는다. 숨기는 것이 아니라 처음부터 옮기지 않는다.
- 노션 원문을 그대로 올리지 않고 공개용 요약본만 올린다.
- 제외: 개인 맞춤 내용(개인 행동 지침, 자산·보유·구직 등 사생활), 부동산 매입가·월세·보증금·분양가, 채용 공고번호와 지원 상세, 내부 메모, 운영자의 이름·닉네임.
- 비공개 표시(`private`)와 개인 전용 블록(`actions`, `side.career`)은 입력에서 금지한다.

## 안전장치
- 입력의 `private` 표시와 개인 전용 블록은 생성 전에 실패한다. 실패하면 기존 생성 파일은 바뀌지 않는다.
- 금지 패턴(`content/_site.json`의 일반 패턴 + 로컬 전용 `보관/blocklist.local.txt`)은 입력 JSON의 모든 문자열과 생성된 HTML 전체(속성·메타 포함)에서 검사한다. 걸리면 아무것도 쓰지 않는다.
- 오류 메시지는 파일·필드·규칙만 알리고 걸린 원문은 다시 출력하지 않는다.
- 필수 항목이 빠지거나 출처 URL이 http(s)가 아니면 생성이 실패한다.
- 자동 검사는 모든 개인 정보를 찾지 못한다. 무엇을 옮길지는 사람이 먼저 고른다.
- 자동화 전까지 사이트 반영은 미리보기 확인 후 승인받고 한다.

## 이번에 하지 않는 것
검색, 댓글, 다크모드, RSS, 매일 자동 게시 예약 작업(공개 규칙 확정 후 다음 단계).

## 개정
- 2026-10-13: 공개 범위를 일반 독자용으로 확정했다. 개인 맞춤 내용을 공개 입력에서 제거하고, 사이트 이름을 'dogcowai 경제브리핑'으로 바꿨다.
- 2026-10-14: 기사 id·출처 필수, 핵심 1분과 기사 연결, 기준일·일정 검사, 기사 구성 라벨, 홈의 주요 기사·분야별 보기, 소개 페이지, sitemap·robots·feed, 수집·링크 검사 도구를 추가했다. 건수 표기는 실린 기사 수로 바꿨다.
- 2026-10-14 (탐색): 메뉴에 지금 있는 곳을 표시하고(홈, 날짜별 브리핑, 소개), 하위 페이지에 위치 줄을 넣었다. 일별 페이지에 차례를 넣고, 누를 수 있는 제목에는 밑줄을 두었다. 회색 상자와 알약 모양 버튼은 선과 줄 목록으로 바꿨다. 가장 중요한 이동 하나(홈의 전체 읽기)만 버튼이다. 내용은 바꾸지 않았다.
- 2026-10-14 (읽는 순서): 홈은 소개글 → 오늘의 주요 뉴스 → 펼쳐 읽는 브리핑 순서다. 일별 페이지는 가장 중요한 뉴스 → 핵심 1분 → 분야별 대표 기사 하나와 '더 보기' 순서다. 메뉴는 오늘의 주요 뉴스, 날짜별 뉴스 브리핑, 소개다. 차례는 뺐다. 접힌 기사로 가는 링크는 스크립트가 펼쳐 준다.
- 2026-10-14 (통일): 펼침은 모두 같은 말을 쓴다(닫힘 "… 더 보기", 열림 "… 접기"). 분야는 늘 같은 순서다: 이름과 건수, 요약, 대표 기사, 더 보기(기사가 더 있을 때), "지난 ○○ 기사 모아 보기". 시장 수치 한 줄, 분야별 모아 보기 페이지(`/topic/<분야 id>/`), 기사마다 "이 기사의 주소", 구역 한 줄 설명을 추가했다. 분야 id 는 날짜가 달라도 같은 분야면 같아야 한다.
- 2026-10-14 (누르는 곳 구분): 누를 수 있는 것은 모두 링크 색(짙은 청록)이다. 다른 곳으로 가는 줄에는 오른쪽에 ›, 펼치는 버튼에는 테두리와 + 가 있다. 기사 제목, 핵심 1분, 시장 수치는 누르는 곳이 아니라서 검은 글씨다. 안내 문장("누르면 …로 이동합니다")은 모두 뺐다. 사실만 있는 기사는 "무슨 일이 있었나" 소제목을 생략한다. 스타일 파일을 한 벌로 다시 썼다.
- 2026-10-14 (이름): 사이트 이름을 '다섯 시 경제'로 바꿨다. 새벽 5시와 오후 5시에 갱신한다는 뜻이다. 주소(dogcowai.com)와 저장소 이름은 그대로다. 갱신 시각을 바꾸면 이름과 소개글도 함께 본다.
- 2026-10-14 (페이지 나누기): 한 페이지에 모든 내용을 담던 구조를 나눴다. 기사마다 페이지가 있고(`/news/날짜/기사id/`), 일별 브리핑은 그날 기사의 목록이다. 홈은 소개와 오늘의 주요 뉴스만 두고 브리핑으로 가는 버튼을 둔다. 분야 목록 페이지(`/topic/`)를 추가했다. 메뉴는 홈, 날짜별, 분야별, 소개다. 분야 바로가기 띠와 그 스크립트는 없앴다. 예전 주소 `/news/날짜/#기사id` 는 일별 브리핑의 그 기사 줄로 간다.
